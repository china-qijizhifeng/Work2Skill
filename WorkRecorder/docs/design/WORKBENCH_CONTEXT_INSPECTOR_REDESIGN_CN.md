# Workbench Context Inspector 复刻设计稿

本轮只解决一个核心问题：点开一条保存记录后，右侧不再像“调试信息栏”，而要像一个真正的 **Agent 预览检查器**。用户应该一眼看懂：这条 Chrome 上下文默认会给 Agent 什么，哪些材料可按需加载，哪些原始材料保持锁定。

## 参考目标

参考图：`.qa/workbench/展开.png`

当前问题集中在右侧展开区：

- 右侧内容堆叠太松，首屏看不到完整证据链。
- tabs 太像开发工具，不像产品的主视图。
- “Agent 默认会看到什么”说明过长，没有一个明确的主视觉。
- 默认可见、按需加载、默认锁定没有形成清晰矩阵。
- 证据栈像日志，缺少产品辨识度。

## 新信息结构

右侧默认首屏固定为下面顺序：

1. Header：页面标题、来源、时间、关闭按钮。
2. 按需查看：截图、文本、原料、诊断的轻量入口，不作为主视觉。
3. Agent 预览：Agent 将读取的安全内容。
4. 上下文材料：默认可见、按需加载、默认锁定三组矩阵。
5. 证据栈：NOTE / TXT / TITLE / HTML / PNG / DOM 等证据行。
6. 共享模式：安全摘要、工作上下文、完整证据包。
7. 信任状态条：本地保存、原始材料锁定、发送前确认。

底部“发送安全摘要给 Agent”本轮不做。视觉上只保留“发送前确认”占位，并写明当前仅预览，避免出现还没接通的假动作。

## 视觉规则

- 背景采用珍珠白和雾银，少量棱镜反射，不大面积青色铺底。
- Tiffany blue 只用于品牌、选中态、安全摘要和主状态。
- 按需加载使用蓝色，默认锁定使用琥珀/暖灰。
- 字号整体收敛，正文尽量 11.5-12.5pt，卡片标题 13-15pt。
- 右侧 Inspector 是最高层浮板，但阴影要轻，边框要精密，不做强发光。
- 中间选中卡片只加强边框和轻外发光，不大改信息结构。

## Round 07-15 的复刻边界

这次复刻不追求把参考图逐像素拷贝成一张静态图片，而是把参考图背后的产品心智落到真实 App 里：

- 左侧是 macOS 本地控制中心的稳定导航，不展示内部工程词。
- 中间是保存过的上下文库，用户能通过筛选快速判断“这条材料能不能给 Agent 用”。
- 右侧是发送前检查器，核心问题只有一个：Agent 会看到什么，哪些材料被锁住。
- 真实 event 数据必须能进入截图链路，不能只靠 mock。

本轮明确不接“发送给 Agent”的真实动作。底部按钮只做“发送前确认”的视觉占位，并清楚写明当前仅预览，避免误导用户。

## 真实数据展示规则

真实网页 evidence 可能带有采集管线的内部说明，比如 OCR 的 `Visual OCR evidence`、安全提示或采集声明。Workbench 是用户界面，不应该把这些内部前缀直接展示在右侧主预览里。

展示层的原则：

- Agent 预览只显示用户能读懂的摘要、选区文本、网页正文状态和材料数量。
- OCR / DOM / raw / a11y 等内部来源只出现在材料明细、诊断或锁定材料里。
- 长正文只展示字数和可读状态，正文内容进入“按需加载/深入查看”，不在首屏塞满。
- unknown artifact 不能被吞掉，必须进入锁定材料计数。
- 真实数据 fixture 必须随测试代码入库；缺失时测试失败，不能因为 `.qa` 被忽略而悄悄跳过。
- 真实数据渲染时，中间选中卡和右侧 Inspector 必须来自同一个 event，避免出现“右侧是真的、左侧是 mock”的误导。

## 验收标准

- 右侧在 `overview-selected` 参考视口内完整显示到信任状态条。
- 默认首屏不出现大号 tabs，但保留清晰的截图、文本、原料、诊断入口。
- “Agent 预览”必须是右侧视觉核心。
- 三个材料状态的颜色职责清楚，不再一屏青绿色。
- 证据栈必须是一组紧凑行，不是松散说明卡。
- 长中文、长 URL、长选区文本不会撑爆布局。
